# requmexre v1.0 plan

Status: proposed after v0.5. v0.5 lives on `main` only — no tag, no GitHub
release. No v1.0 work has started.

Goal: freeze the current model as a stable, citable v1.0 without widening its
scope.

## In scope

- **Schema v1.0**: bump the `$id` and version metadata to v1.0; keep S1–S10 and
  R1–R8 unchanged; preserve v0.5 compatibility.
- **Versioning**: v1.0.0 would be the first tagged version. Decide whether it
  gets an annotated tag and a GitHub release, and who can push them.
- **Citation**: a `CITATION.cff`, the README citation and a DOI decision.
- **Documentation**:   README, SKILL, RULES, mappings, VERSION_NOTES and BREAKAGES at
  v1.0; remove the v0.5 draft language.
- **Validation**: 24/24 fixtures, 3/3 published plans, draft 2020-12, site build,
  and green CI before any tag.

## Out of scope

- New funders, fields, rules or scope changes.
- Preliminary/own research, Horizon D&C/capacity, DFG duration/diversity/data
  handling/publications/funding, SNSF milestones/ethics/budget, and standalone
  DFG/SNSF results sections.
- A truth or citation checker.
- New published plans.

## Decisions before work starts

1. **Citation author**: use `avvohacker` or a full name/ORCID? The current Git
   author is `avvohacker`.
2. **Licence**: `LICENSE.md` says all rights reserved. A citable DOI and a CFF
   file need a licence decision and an SPDX identifier.
3. **DOI**: optional. Zenodo needs a tagged release; without a tag, cite the
   commit instead.
4. **Tag and release**: v0.5 was left on `main` untagged. v1.0 can either open
   the tag series (`v1.0.0` plus a GitHub release with `VERSION_NOTES.md` as notes) or
   stay untagged like v0.5. A tag push needs GitHub credentials: the cloud
   workspace has none, and `cloud_git` pushes commits only.

## Steps

1. **Freeze review** — diff v1.0 against v0.5 at `e2ef265` / `178f18d` on
   `main`; confirm no schema or rule change; record the compatibility statement.
2. **Citation** — create `CITATION.cff`; resolve author, licence and DOI;
   validate the CFF; update the README citation.
3. **Version bump** — schema `$id`/description, validator banner, README, SKILL,
   mappings, site footer, BREAKAGES and VERSION_NOTES.
4. **CI gate** — run the validators, draft-schema check and site build; wait for
   the validate and pages workflows; a red run blocks the version commit.
5. **Versioning** — if the tag decision is yes: commit the version/docs, tag
   `v1.0.0` with the release notes, push the tag, verify the tag workflow,
   publish the release. If no: stop at the version commit on `main` and record
   the untagged state in the README and VERSION_NOTES.
6. **Post-release** — check the citation resolves, the README is current, and no
   v0.5 draft or "schema v0.5" reference remains.

## Acceptance criteria

- `schema/requmexre.schema.json` is draft 2020-12 and has the v1.0 `$id`.
- `python3 validate.py` passes 24/24; published plans pass 3/3.
- The validate and pages workflows are green on the version commit.
- `CITATION.cff` is valid and matches the README.
- No current v0.5 draft or "schema v0.5" reference remains outside history.
- Either a `v1.0.0` tag and GitHub release with `VERSION_NOTES.md` as notes exist, or
  the untagged decision is recorded in the README and VERSION_NOTES and this plan.

## Risks

- A licence/DOI decision can block the citation. Resolve it before the version
  bump.
- A schema freeze is a compatibility promise: do not add fields during the
  version work.
- v0.5 carries no tag, so there is no earlier tag or tag CI run to point at; the
  freeze review must rely on the v0.5 commits on `main`.
- A tagged v1.0 needs GitHub credentials for the tag push; arrange that access
  before step 5 or fall back to the untagged route.
- The Pages workflow only runs on `main` changes to its path filter; a tag does
  not rebuild Pages. Verify the version commit run on `main` and, if tagged, the
  tag validate run.
- CI cannot be verified without public API access or a GitHub token; use the
  public runs page as a fallback and record the limitation.

## Done when

v1.0 is citable, documented and green in CI, with the tag decision applied and
recorded; no open roadmap item before v1.1.
