# requmexre v1.0 plan

Status: version bump applied at v1.0 (schema, validator, site, SKILL, mappings,
README, VERSION_NOTES, BREAKAGES, citation). v0.5 and v1.0 live on `main` only —
no tag, no GitHub release. Decision: v1.0 stays untagged on `main`.

Goal: freeze the current model as a stable, citable v1.0 without widening its
scope.

## In scope

- **Schema v1.0**: bump the `$id` and version metadata to v1.0; keep S1–S10 and
  R1–R8 unchanged; preserve v0.5 compatibility.
- **Versioning**: resolved as untagged — no `v1.0.0` tag and no GitHub release;
  the version is recorded by the `$id`, README, VERSION_NOTES and CITATION.cff.
- **Citation**: a `CITATION.cff`, the README citation and a DOI decision.
- **Documentation**: README, SKILL, RULES, mappings, VERSION_NOTES and BREAKAGES at
  v1.0; remove the v0.5 draft language.
- **Validation**: 24/24 fixtures, 3/3 published plans, draft 2020-12, site build,
  and green CI before the version commit.

## Out of scope

- New funders, fields, rules or scope changes.
- Preliminary/own research, Horizon D&C/capacity, DFG duration/diversity/data
  handling/publications/funding, SNSF milestones/ethics/budget, and standalone
  DFG/SNSF results sections.
- A truth or citation checker.
- New published plans.

## Decisions before work starts

1. **Citation author** — resolved: `avvohacker`, the Git author. `CITATION.cff`
   uses `name: avvohacker`; a full name or ORCID can be added later without
   touching the model.
2. **Licence** — resolved for now: all rights reserved, as `LICENSE.md` says.
   `CITATION.cff` points at the licence text with `license-url` and carries no
   SPDX identifier. Moving to MIT, Apache-2.0 or a dual code/text licence is a
   decision for the copyright holder, and a one-line change in `CITATION.cff`
   and `LICENSE.md`.
3. **DOI** — resolved: none. A DOI needs a tagged, archived release (Zenodo or
   equivalent); v0.5 has no tag and v1.0 does not require one. Revisit only if
   the tag decision becomes yes.
4. **Tag and release** — resolved: v1.0 stays untagged on `main`, like v0.5. No
   `v1.0.0` tag, no GitHub release, no release page. The cloud workspace has no
   Git credentials and `cloud_git` pushes commits only, so the tag route would
   need access arranged outside this workflow; it is not taken.

## Steps

1. **Freeze review** — diff v1.0 against v0.5 at `e2ef265` / `178f18d` on
   `main`; confirm no schema or rule change; record the compatibility statement.
2. **Citation** — bump `CITATION.cff` to `version: "1.0.0"`; keep author,
   licence and the no-DOI decision unless they change; validate the CFF; update
   the README citation.
3. **Version bump** — schema `$id`/description, validator banner, README, SKILL,
   mappings, site footer, BREAKAGES and VERSION_NOTES.
4. **CI gate** — run the validators, draft-schema check and site build; wait for
   the validate and pages workflows; a red run blocks the version commit.
5. **Versioning** — applied: the version commit stays on `main`; the untagged
   state is recorded in the README, VERSION_NOTES and this plan. No tag is
   created and no release is published.
6. **Post-version** — check the citation resolves, the README is current, and no
   v0.5 draft or "schema v0.5" reference remains.

## Acceptance criteria

- `schema/requmexre.schema.json` is draft 2020-12 and has the v1.0 `$id`.
- The `$id` resolves: the Pages build publishes the schema at its `$id` path.
- `python3 validate.py` passes 24/24; published plans pass 3/3.
- The validate and pages workflows are green on the version commit (validate #31
  and pages #21 on `3a78b7a`).
- `CITATION.cff` is valid and matches the README.
- No current v0.5 draft or "schema v0.5" reference remains outside history.
- No `v1.0.0` tag and no GitHub release exist; the untagged decision is recorded
  in the README, VERSION_NOTES and this plan, and the citation carries no DOI.

## Risks

- A licence change before v1.0 must land in `LICENSE.md`, `CITATION.cff` and
  the README together, or the citation and the repository disagree.
- A schema freeze is a compatibility promise: do not add fields during the
  version work.
- v0.5 carries no tag, so there is no earlier tag or tag CI run to point at; the
  freeze review must rely on the v0.5 commits on `main`.
- Untagged means no release page and no versioned archive: a reader pins the
  commit. That is accepted; the README and VERSION_NOTES say so.
- The Pages workflow only runs on `main` changes to its path filter; a tag does
  not rebuild Pages. Verify the version commit run on `main` only.
- CI cannot be verified without public API access or a GitHub token; use the
  public runs page as a fallback and record the limitation.

## Done when

v1.0 is citable, documented, untagged on `main` as decided, and green in CI;
no open roadmap item before v1.1.
