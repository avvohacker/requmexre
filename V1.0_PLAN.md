# requmexre v1.0 plan

Status: proposed after the v0.5 release. No v1.0 work has started.

Goal: freeze the current model as a stable, citable v1.0 without widening its
scope.

## In scope

- **Schema v1.0**: bump the `$id` and version metadata to v1.0; keep S1–S10 and
  R1–R8 unchanged; preserve v0.5 compatibility.
- **Release engineering**: annotated tag `v1.0.0`, release notes, and the
  validate/pages/draft-schema gates.
- **Citation**: a `CITATION.cff`, the README citation and a DOI decision.
- **Documentation**: README, SKILL, RULES, mappings, RELEASE and BREAKAGES at
  v1.0; remove the v0.5 draft language.
- **Validation**: 24/24 fixtures, 3/3 published plans, draft 2020-12, site build,
  and green CI before tagging.

## Out of scope

- New funders, fields, rules or scope changes.
- Preliminary/own research, Horizon D&C/capacity, DFG duration/diversity/data
  handling/publications/funding, SNSF milestones/ethics/budget, and standalone
  DFG/SNSF results sections.
- A truth or citation checker.
- New published plans.

## Decisions before work starts

1. **Citation author**: use `avvohacker` or a full name/ORCID? The current Git
   author is `avvohacker`.
2. **Licence**: `LICENSE.md` says all rights reserved. A citable DOI and a CFF
   file need a licence decision and an SPDX identifier.
3. **DOI**: optional. If wanted, deposit v1.0 on Zenodo (or use a GitHub release)
   and put the DOI in `CITATION.cff` and the README.

## Steps

1. **Freeze review** — diff v1.0 against v0.5; confirm no schema or rule change;
   record the compatibility statement.
2. **Citation** — create `CITATION.cff`; resolve author, licence and DOI; validate
   the CFF; update the README citation.
3. **Version bump** — schema `$id`/description, validator banner, README, SKILL,
   mappings, site footer, BREAKAGES and RELEASE.
4. **CI gate** — run the validators, draft-schema check and site build; wait for
   the validate and pages workflows; a red run blocks the tag.
5. **Release** — commit the version/docs, tag `v1.0.0` with the release notes,
   push the tag, verify the tag workflow, publish the GitHub release.
6. **Post-release** — check the citation resolves, the README is current, and no
   v0.5 draft wording remains.

## Acceptance criteria

- `schema/requmexre.schema.json` is draft 2020-12 and has the v1.0 `$id`.
- `python3 validate.py` passes 24/24; published plans pass 3/3.
- The validate and pages workflows are green on the release commit; the tag
  workflow is green.
- `CITATION.cff` is valid and matches the README.
- No current v0.5 draft or "schema v0.5" reference remains outside history.
- A v1.0 tag and GitHub release exist with `RELEASE.md` as the notes.

## Risks

- A licence/DOI decision can block the citation. Resolve it before the version
  bump.
- A schema freeze is a compatibility promise: do not add fields during the
  release.
- The Pages workflow only runs on main changes to its path filter; a tag does
  not rebuild Pages. Verify both the main release commit and the tag validate
  run.
- CI cannot be verified without public API access or a GitHub token; use the
  public runs page as a fallback and record the limitation.

## Done when

v1.0 is tagged, citable, documented and green in CI, with no open roadmap item
before v1.1.
